# Interface review - 10 September 2026

The review focused on completing everyday parking tasks on phones and desktops. Changes were developed against an isolated local database, using sample records and a simulated camera.

## Improvements

- Fixed the mobile sidebar remaining visible when reduced motion was enabled. The menu icon now has a visible outline and readable color. Closed navigation is excluded from keyboard focus; the open drawer keeps focus inside, supports Escape, and restores focus to its trigger.
- Added an immediately visible **Open scanner** action to the guard dashboard. Summary figures use a compact two-column layout on small phones.
- Removed repeated scanner instructions and placed the device/remote choice next to the page title. Gate selection and camera controls share a row on phones; the camera view fits much higher on the page.
- Added **Manual Lookup** to guard navigation and condensed the manual page's scanner shortcut.
- Fixed panels growing beyond the phone viewport and hiding content. Improved text wrapping, aligned panel edges, and made mobile form text 16 pixels.
- Replaced numbered registration steps with clearly named student tabs. Tabs now expose the correct accessibility roles, support arrow keys/Home/End, retain their section on reload, and respond to section links.
- Improved light/dark text contrast in headings, report summaries, report filters, and scanner mode selection. Scrollable report, visitor, occupancy and parking-history regions are reachable by keyboard.
- Updated cached stylesheet versions and the service worker to v36.

## Verification

- `npm test`: 93 checks passed.
- `npm run test:camera`: 26 camera and scanner browser tests passed.
- `npm run test:ui`: 10 tests passed, covering keyboard navigation, tabs, focus management, phone action placement and accessibility checks across desktop, phone and dark phone profiles. Two desktop cases are intentionally skipped because they test the phone drawer/layout.
- `scripts/review-ui.js`: 39 page/profile checks across 13 views, with no browser errors, clipped main panels, or detected accessibility violations. Includes registration, directory, stickers, accounts, reports, slots, recovery, visitors, security, guard dashboard, manual lookup and remote camera.
- Additional checks at 320, 768 and 1440 pixels covered slots, visitor passes, student directory and account security in dark mode. The login screen also passed accessibility checks on phone and desktop.

Browser checks use Chromium and axe-core. They do not constitute a full accessibility certification or replace testing on physical phones, Safari, and assistive technology.

To repeat the review, start a local application with test admin/guard credentials configured in `.env`. For a server running on port 3019:

```powershell
$env:E2E_BASE_URL = 'http://127.0.0.1:3019'
npm run test:ui
$env:UI_REVIEW_BASE_URL = 'http://127.0.0.1:3019'
node scripts/review-ui.js
```

The screenshot audit writes its results to `test-results/ui-review`, or to `UI_REVIEW_ARTIFACT_DIR` when configured. It does not submit registration or parking movements.
